The brief

Problem

Command-line downloaders work until they do not, and when one fails mid-playlist the error arrives as a stack trace with no indication of which items succeeded.

Who it is for

People archiving media they already have access to, who want a local copy and a queue they can see.

Approach

A Tkinter interface wraps a downloader module split by responsibility: one part resolves metadata, one handles the fetch, and the interface stays out of both. Playlist items are queued individually so a single failure does not abandon the rest, and the queue reports per-item state.

Personal contribution

Sole author. Includes a pytest suite covering the metadata and playlist logic.

Decisions that mattered

These are the choices that shaped the code — the ones worth explaining, rather than a feature list.

Queue items separately rather than as one playlist job

Treating a playlist as one unit means one bad item costs you the other thirty-nine. Per-item jobs turn a total failure into a partial success, which is the failure mode you actually want.

Separate metadata resolution from downloading

Resolution is fast, fallible and worth caching; downloading is slow and stateful. Splitting them made each testable without the other, which is why there is a test suite at all.

A desktop interface for a tool that is easier as a script

A script is faster to write and worse for the person watching a long queue. The interface exists to answer one question continuously: what is happening right now.

Limitations, stated plainly

  • Depends on yt-dlp, so upstream site changes can break extraction until the dependency updates.
  • Downloading media may conflict with a platform's terms of service; this is a personal archival tool, not a redistribution one.
  • No packaged installer is recorded, so it runs from source.
  • It runs from the repository rather than from a hosted URL.

What this is not: there is no public deployment for this project, so it should not be described as live, available, in production, or used by anyone. Claims about scale or reliability would require measurements that do not exist.

What it taught
