The brief

Problem

Campus accommodation changes hands in WhatsApp groups and on paper. A student cannot compare two options side by side, cannot tell whether a listing is still live, and cannot see who else is looking. A landlord, meanwhile, has no idea whether anyone read their listing at all.

Who it is for

Two distinct users with conflicting needs in one product: students looking for a room near campus, and landlords who need their listings seen and their enquiries organised.

Approach

One React single-page app with role-based routing over a Django REST Framework API. Listings carry their own analytics: view tracking, unique-view tracking, saved listings and action tracking, feeding a landlord-only aggregate dashboard.

Personal contribution

Sole author of the frontend and backend in the public repository: routing architecture, the listings data flow, the analytics endpoints and the dashboard.

Decisions that mattered

These are the choices that shaped the code — the ones worth explaining, rather than a feature list.

Role routing at the router, not in the components

After sign-in a user is redirected by role, and cross-role routes are blocked with redirects inside the route definition rather than by hiding links. A student cannot render a landlord screen by editing the URL, because the guard is not in the UI.

Analytics through the cache, not a write per request

Every page view writing a row would make a cold SQLite deployment fall over. View tracking is de-duplicated in the Django cache with a 60-second window for repeat views and a 24-hour window for the unique counter, so the database only sees genuinely new attention.

Aggregate endpoints kept outside the DRF router

Landlord analytics and 'my listings' are separate, landlord-scoped endpoints, so an aggregate query can never be reached with a student's session.

Limitations, stated plainly

  • There is no public deployment, so it runs locally from the repository. Nothing about it should be described as live.
  • Messaging is modelled in the data layer but the repository does not document a delivery guarantee.
  • No test suite is present in the repository.

What this is not: there is no public deployment for this project, so it should not be described as live, available, in production, or used by anyone. Claims about scale or reliability would require measurements that do not exist.

Rate-limited view tracking. This is the decision the whole analytics feature rests on: counting attention through the cache instead of the database. The 24-hour unique key is what makes a landlord's numbers mean something, and the 60-second key is what stops a refresh loop from inflating them.

What it taught

The hardest part was not the marketplace, it was the second user. Supporting a landlord changed the data model, the routing and the analytics at the same time — which is the argument for designing the second role before the first one is polished.
