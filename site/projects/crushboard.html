The brief

Problem

Dating apps fail at the same thing every time: the profile is the product, so everyone optimises the profile, and the first impression becomes a performance rather than a signal. Inverting the format is a way to find out what changes when the pressure to present is removed.

Who it is for

People who find conventional dating apps exhausting, and anyone who wants to see what happens when the same matching problem is framed as hiring.

Approach

Listers publish positions describing who they are looking for. Applicants submit anonymously through a shared link; a dedup pipeline prevents repeat submissions. The lister reviews candidates on a dashboard and unseals identities one at a time, by choice, rather than seeing everything at once. The interface is a deliberately straight-faced enterprise tool: no hearts, no pink, no bubbly motion, because the joke only works if the framing never breaks.

Personal contribution

Sole author. Runs in a seeded in-memory demo mode with no environment variables, so the whole pipeline is reviewable without provisioning anything.

Decisions that mattered

These are the choices that shaped the code — the ones worth explaining, rather than a feature list.

One-way reveal, chosen by the lister

Identity is withheld until the lister decides to unseal it. That is the whole mechanism: it moves the point of judgement away from the photograph and back to the listing, which is the only reason the concept is interesting.

Demo mode runs with zero configuration

With no env vars the app boots a seeded in-memory backend with live listings, candidates and the full pipeline. Anyone reviewing it gets the product instead of a setup guide, and the Supabase path stays available for anything real.

The masking happens in the database

A masking view and row-level security in the initial migration withhold identity at the data layer, so an unsealed name is released deliberately rather than being hidden by the client and revealed by devtools.

Limitations, stated plainly

  • Anonymous applications plus withheld identity is a combination with real abuse potential; there is no moderation or reporting flow yet.
  • Demo data resets on server restart, and the Supabase path requires running two migrations plus deploying two edge functions before it is functional.
  • It runs from the repository rather than from a hosted URL.

What this is not: there is no public deployment for this project, so it should not be described as live, available, in production, or used by anyone. Claims about scale or reliability would require measurements that do not exist.
