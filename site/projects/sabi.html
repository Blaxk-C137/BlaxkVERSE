The brief

Problem

Cloud tutors either cannot hear the student properly or answer from a generic textbook instead of the lecturer's material. Accent-heavy speech recognition and offline study both tend to be afterthoughts in study assistants built elsewhere.

Who it is for

A student who revises out loud, on a laptop, in a place with unreliable bandwidth, using their own lecturer's slides.

Approach

A deliberate division of labour: the language model handles text only. Speech recognition runs locally through Whisper small on the student's machine; speech output uses on-device browser voices with a selected accent. Course PDFs are the tutor's stated source of truth.

Personal contribution

Sole author. The repository includes the speech queue with explicit per-reply cancellation, the local voice client, the board renderer, model installation scripts and tests for the voice client.

Decisions that mattered

These are the choices that shaped the code — the ones worth explaining, rather than a feature list.

Gemini writes; the device speaks and listens

Stated as a rule rather than a preference, because it is the whole reason the product is privacy-credible: no audio is sent to a speech API. The listening path is local Whisper, the speaking path is on-device voices.

Only free-tier models appear in the list — on purpose

The model picker is restricted to free Flash and Flash-Lite identifiers. The app is structurally incapable of quietly billing a student for a Pro model.

One speech queue for the whole application

Sentences are synthesised into clips and played back to back through a single audio context, fetching the next clip while the current one plays. Cancellation is explicit and per reply, so a re-render cannot cut a tutor off mid-sentence and a cancelled reply drops only its own clips.

Client-side speech fallback rather than silence

If the local server voice is unavailable, clips fall back to the browser's built-in speech so the tutor still talks.

Limitations, stated plainly

  • First run downloads a local speech model (about 250 MB) — documented up front as a one-time cost.
  • Desktop Chrome or Edge is strongly recommended; the README states that Firefox speech support is weaker.
  • Barge-in is deliberately narrow: one reply is one session, which keeps cancellation predictable but means overlapping speech is not supported.
  • It runs from the repository rather than from a hosted URL.

What this is not: there is no public deployment for this project, so it should not be described as live, available, in production, or used by anyone. Claims about scale or reliability would require measurements that do not exist.

The speech queue contract. The comment block is the design document. It states what a session is, why cancellation is explicit instead of a side effect of re-rendering, and what happens when the local voice is missing — three things that are usually discovered as bugs rather than decided.

What it taught

Splitting speech from language is the decision everything else follows from — and it made the queue the most delicate part of the codebase, because the student has to be able to interrupt the tutor instantly without the tutor losing its place.
