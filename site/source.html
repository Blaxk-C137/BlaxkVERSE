How the ingestion is designed to work

This site is static, and the pages you are reading were built from a verification pass rather than fetched live in your browser. The designed production pipeline — documented in full in the repository — is:

GitHub API  →  server fetcher  →  repository allowlist  →  metadata normalisation
            →  content cache  →  server-rendered pages  →  project visualisations
  • Only an explicit allowlist is ever published; a repository existing on GitHub is not a reason to show it.
  • Excerpts are pinned by commit SHA, path and line range, and pre-screened by a secrets and high-risk content filter before publication.
  • API responses are cached; a GitHub outage degrades to clearly-labelled stale data rather than an empty page or a broken layout.
  • "Updated" is shown with a timestamp. A single push is never described as "actively maintained".
  • Snippets are rendered as inert highlighted text. Nothing from a repository is ever executed in a visitor's browser.
